# neoved-chat-worker

Виджет обратной связи на сайте ↔ amoCRM. Посетитель оставляет имя, почту,
телефон и ник Telegram, пишет вопрос — в amoCRM появляется сделка на этапе
«Новая заявка», менеджер отвечает **обычным примечанием прямо в карточке**,
и ответ возвращается человеку в тот же чат на сайте.

Ставится на Tilda (и любой другой сайт) одной строкой:

```html
<script src="https://neoved-chat.strelnikov2302.workers.dev/widget.js" defer></script>
```

## Что происходит по шагам

1. **Форма.** Виджет шлёт `POST /api/start`: имя, почта, телефон, ник, текст,
   адрес страницы.
2. **Поиск контакта.** По почте → по телефону → по нику Telegram. Первое
   совпадение выигрывает. Телефон сравнивается цифрами: `+7 (926) 571-72-19`
   и `79265717219` — один и тот же человек.
3. **Сделка.**
   - контакта нет → `POST /api/v4/leads/complex` создаёт сделку вместе с
     контактом в воронке «Продажи клиентам» на этапе «Новая заявка»;
   - контакт есть, открытой сделки нет → новая сделка на том же этапе;
   - открытая сделка есть → `PATCH` двигает её на этап «Новая заявка»
     **внутри её собственной воронки** и добавляет тег `site_chat`.
4. **Сообщение.** Текст падает примечанием: первое — сводка с контактами,
   дальнейшие — просто реплики клиента.
5. **Ответ.** Менеджер пишет примечание в ленте сделки → amoCRM шлёт вебхук
   `note_lead` → воркер убеждается, что примечание написано человеком и сделка
   помечена тегом виджета, и кладёт текст в очередь этой сделки → виджет
   забирает её опросом `/api/poll` и показывает в чате.

## Как воркер отличает ответ менеджера от эха

Клиентские сообщения тоже становятся примечаниями, и вебхук приносит их
обратно. Различаются они по полю `created_by` в вебхуке: у примечаний,
созданных по API (наши собственные и чужих интеграций), там `0`, у реплики
живого менеджера — его id пользователя. Метка «своё примечание» в KV осталась
подстраховкой, но одна она не годится: вебхук приходит быстрее, чем запись
KV расходится по регионам, — на этом сообщение клиента возвращалось ему же.

По той же причине признак «сделку ведёт виджет» проверяется не в KV, а тегом
на самой сделке — его amoCRM отдаёт актуальным сразу.

Следствие: ответ, отправленный клиенту **через другую интеграцию** (например,
менеджер написал в Telegram, и `tg-amo-worker` продублировал это примечанием),
в виджет не попадёт — у такого примечания `created_by = 0`.

## Почему примечания, а не «Чаты» amoCRM

Двусторонний чат amoCRM (amojo) требует канала, зарегистрированного через
партнёрский аккаунт в amoMarket: обычной интеграции с долгосрочным токеном его
не выдают. Примечания доступны любому токену и работают в обе стороны — тем же
способом уже живёт соседний `tg-amo-worker`.

Побочный эффект: воркер видит **все** обычные примечания сделок с тегом
`site_chat`. Если менеджер пишет в такой сделке внутреннюю заметку, клиент
увидит её в чате. Чтобы этого не было, задайте `REPLY_PREFIX` (например, `+`) —
тогда клиенту уйдут только примечания, начатые с этого знака.

## Адреса

| Адрес | Что делает |
|---|---|
| `GET /widget.js` | сам виджет, отдаётся с `Access-Control-Allow-Origin: *` |
| `POST /api/start` | заявка из формы → контакт + сделка + примечание, отдаёт `sid` |
| `POST /api/send` | следующее сообщение клиента → примечание в ту же сделку |
| `GET /api/poll?sid=…&after=…` | ответы менеджера, которых клиент ещё не видел |
| `POST /amo/<HOOK_SECRET>` | вебхук amoCRM на событие `note_lead` |
| `GET /debug/<HOOK_SECRET>` | последние 50 решений воркера |
| `GET /health` | проверка живости |

## Деплой

```powershell
$env:CF_API_TOKEN='...'   # права: Workers Scripts:Edit, Workers KV Storage:Edit
node deploy.mjs
```

Скрипт создаёт KV namespace (при первом запуске пишет `KV_ID` в `.env`),
заливает `worker.js` + `widget.js` (текстовым модулем), включает
workers.dev-поддомен и подписывает вебхук в amoCRM на событие `note_lead`.
Повторный запуск безопасен: если вебхук с таким адресом уже есть, подписка
пропускается — вопреки документации, этот аккаунт на повторный `POST` того же
адреса отвечает 400 «Invalid URL».

Почему Node, а не `curl`, как у соседних воркеров: на этой машине `curl.exe`
не договаривается по TLS с `api.cloudflare.com` (ошибка 35, HTTP 000), а
встроенный в Node `fetch` ходит туда нормально. Запускать лучше по полному пути
(`node C:\…\neoved-chat-worker\deploy.mjs`) — из-за кириллицы в пути PowerShell
иногда роняет запуск с exit 5.

## Настройки (`.env`)

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `PIPELINE_ID` | `9018718` | воронка «Продажи клиентам» для новых клиентов |
| `STATUS_ID` | `72669522` | её этап «Новая заявка» |
| `NEW_STATUS_NAME` | `Новая заявка` | этап, на который двигаем существующую сделку |
| `TAG_NAME` | `site_chat` | тег, которым помечаются заявки из виджета |
| `EMAIL_FIELD` / `PHONE_FIELD` | `629257` / `629255` | стандартные поля контакта |
| `TG_FIELD` | `996481` | куда пишем ник новому контакту |
| `TG_LOOKUP` | `977339,996481,997749,999219` | по каким полям ищем ник у существующего |
| `ALLOW_ORIGINS` | пусто | пусто — любой домен; иначе список origin через запятую |
| `REPLY_PREFIX` | пусто | если задан, клиенту уходят только примечания с этого префикса |
| `STRIP_PREFIXES` | `Ответ:` | пометки соседних интеграций, которые срезаем из текста |
| `START_LIMIT` / `MSG_LIMIT` | `5` / `60` | заявок с одного IP в час / сообщений на сессию |

## Настройка виджета на странице

```html
<script src="https://neoved-chat.strelnikov2302.workers.dev/widget.js" defer
        data-title="Напишите нам"
        data-subtitle="Отвечаем в рабочее время, обычно в течение 15 минут"
        data-accent="#EE0000"
        data-policy="https://neoved.io/policy"></script>
```

Открыть виджет со своей кнопки: `neovedChat.open()`. Сбросить диалог у себя в
браузере (для тестов): `neovedChat.reset()`.

## Что стоит знать

- **Задержка ответа.** Хранилище — Cloudflare KV, оно eventually consistent:
  ответ менеджера обычно доезжает до чата за несколько секунд, изредка — до
  минуты. Виджет опрашивает сервер раз в 5 секунд, пока раскрыт, и раз в
  30 секунд, когда свёрнут (чтобы зажечь счётчик непрочитанных).
- **Срок жизни диалога** — 30 дней с последнего действия, дальше сессия
  протухает и клиент начинает с формы заново.
- **Один клиент в двух каналах.** Если человек писал и в Telegram-канал, и в
  виджет, обе интеграции работают с одной сделкой. Ответ, написанный менеджером
  в карточке, уйдёт в оба канала; ответ, отправленный из самого Telegram, в
  виджет не попадёт (см. про `created_by` выше). Префикс `Ответ: `, которым
  `tg-amo-worker` помечает исходящие, в чате срезается (`STRIP_PREFIXES`).
- **Антиспам** — грубый счётчик в KV: не больше `START_LIMIT` заявок с одного
  IP в час. KV не атомарен, пара запросов сверх лимита может проскочить.
- **Персональные данные.** В форме есть ссылка на политику обработки — задайте
  её через `data-policy`, иначе ведёт на `https://neoved.io/policy`.
