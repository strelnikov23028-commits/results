# Письмо в поддержку amoCRM: доступ к Chats API (amojo)

Куда отправлять: чат технической поддержки внутри аккаунта (надёжнее всего —
там сразу видно, что пишет владелец аккаунта) либо на **support@amo.tm**.
В теме и первой строке обязательно указать поддомен и ID аккаунта, иначе
запрос будут уточнять.

Что приложить: ничего обязательного, но если попросят — скриншот установленной
интеграции и краткое описание сценария.

---

**Тема:** Запрос канала чатов (Chats API) для аккаунта neoved.amocrm.ru (ID 32132070)

Здравствуйте!

Мы — компания neoved (сайт neoved.io), аккаунт **neoved.amocrm.ru**, ID аккаунта
**32132070**.

Разработали и уже используем собственную интеграцию: виджет чата на нашем сайте,
который заводит сделки в воронке «Чат на сайте», подтягивает контакт и компанию
по ИНН и позволяет менеджеру переписываться с посетителем. Интеграция приватная,
установлена в нашем аккаунте архивом с пользовательским кодом, работает на
API v4 (долгосрочный токен).

Сейчас переписка сохраняется примечаниями в ленте сделки. Мы хотели бы
отображать её как полноценный чат в карточке — так же, как это делают
интеграции мессенджеров: с лентой сообщений, статусами доставки и полем ответа
внизу карточки.

**Просим выдать канал чатов для Chats API (amojo): `channel_id` и
`channel_secret`** для нашей приватной интеграции.

Что мы уже готовы обеспечить со своей стороны:

- подпись запросов по требованиям Chats API — заголовки `Date`, `Content-Type`,
  `Content-MD5`, `X-Signature` (HMAC-SHA1 с секретом канала);
- приём вебхуков на наш сервер (Cloudflare Workers, HTTPS);
- подключение канала к аккаунту методом `POST /v2/origin/custom/{channel}/connect`
  и дальнейшую работу по документации amoCRM.

Подскажите, пожалуйста:

1. Какие данные нужны от нас, чтобы канал выдали (описание интеграции, её ID
   в аккаунте, что-то ещё)?
2. Требуется ли для этого партнёрский статус или публикация интеграции
   в маркете, если канал будет использоваться только внутри нашего аккаунта?
3. Есть ли ограничения по количеству сообщений или иные условия использования?

Готовы предоставить любые дополнительные сведения об интеграции.

## Когда придёт ответ

Как только появятся `channel_id` и `channel_secret`, доставку сообщений
переводим с примечаний на Chats API: транспорт в `worker.js` заменяется, вся
остальная логика (склейка по ИНН/почте/телефону, запрос ИНН и телефона,
кнопки в карточке) остаётся как есть.
