Under the Hood: как запросить у X скрытые метки аккаунта

X открыл исходники ранжирования «For You» и одновременно запустил отчёт, в котором видно, какие visibility-метки система навесила на ваш аккаунт и посты за прошлый календарный месяц. Ниже — путь в интерфейсе, точные условия допуска, структура JSON и полный список из 30 меток, вычитанный прямо из опубликованного кода.

1Что это вообще такое

Under the Hood — страница в настройках X, где аккаунт может скачать агрегированную месячную статистику по меткам ограничения видимости. Это не «детектор теневого бана»: отчёт показывает только формальные метки модерации, которые X реально записал за вами. Слабый охват из-за плохого вовлечения, ранжирующих моделей или скоринга сюда не попадает.

Формат

JSON-файл. Агрегат за месяц, не детализация по каждому посту.

Период

Прошлый календарный месяц по UTC — и только через 10+ дней после его окончания.

Две группы меток

18 меток на посты (TweetSafetyLabels) и 12 на аккаунт (UserSafetyLabels).

Открытый код

Генератор отчёта опубликован: xai-org/x-algorithm → under-the-hood.

2Путь в интерфейсе

Штатный способ — через настройки веб-версии или приложения:

Settings and privacy→ Privacy and safety→ Under the Hood→ Download

Если пункта «Under the Hood» в меню нет — ваш аккаунт не в пилотной группе. Это не ошибка и не признак санкций: страница целиком спрятана за фиче-флагом (см. блок 3).

Про чтение JSON. X прямо предлагает нетехническим пользователям закинуть файл в любого AI-ассистента вместе со ссылкой на GitHub-репозиторий и попросить объяснить. Расшифровка меток лежит рядом с отчётом — таблицы ниже это она и есть.

3Условия допуска — дословно из кода

Проверки жёстко зашиты в underTheHoodReport.User.strato. Все четыре должны выполниться одновременно:

  1. Фиче-флаг включён. under_the_hood_report_enabled, значение по умолчанию — false. Раздаётся выборочной группе; в конфиге также прописана роль birdwatch_team. Именно поэтому у большинства пункта в настройках пока нет.
  2. Аккаунт старше года. minimumAccountAge = 365.days, метка проверки — «Account at least 1 year old».
  3. 10+ постов за отчётный месяц. minimumEligiblePosts = 10, метка — «10 or more posts in the prior month».
  4. Аккаунт не заблокирован. При suspended = true колонка отдаёт Ok.missing — отчёта не будет вообще.

Какой месяц попадёт в отчёт

Берётся предыдущий календарный месяц UTC, но только если с его последнего дня прошло минимум 10 суток (minDaysAfterMonthEnd = 10). Если данные по нему ещё не досчитаны до конца (finalThroughDay не покрывает последний день месяца) — система откатывается ещё на месяц назад. То есть в начале сентября вы, скорее всего, увидите июль, а не август.

Важный нюанс. Если возраст или число постов не дотягивают, X всё равно вернёт объект — но с пустым reportJson и заполненным reportInfo.eligibilityChecks, где по каждой проверке стоит true/false. Так что интерфейс сможет показать вам, чего именно не хватило.

4Как это устроено на уровне запроса

Отчёт отдаётся через GraphQL. В опубликованном коде видна вся цепочка:

  • Публичный алиас — userUnderTheHoodReport типа GraphQlQuery, views = Set(ExternalGraphQl). Ведёт на колонку visibility/under-the-hood/underTheHoodReport.
  • Ключ запроса — пустой (type Key = Unit). Пользователь берётся из сессии: CallContext.authenticatedTwitterUserId(). Чужой аккаунт запросить нельзя — политика доступа AllowTwitterUserId.
  • Форма ответа описана в under_the_hood.thrift.
// under-the-hood/strato/graphql/under_the_hood.thrift
struct UnderTheHoodReportInfo {
  1: optional string reportPeriod              // "July 2026"
  2: optional map<string, bool> eligibilityChecks
}

struct UnderTheHoodReport {
  1: optional i64    generatedAt   (GraphQlEncoding = "Int53")
  2: optional string reportJson    // сам отчёт строкой JSON
  3: optional UnderTheHoodReportInfo reportInfo
}

Честно о пределах. Конкретный queryId персистентного GraphQL-запроса x.com в открытый репозиторий не выкладывали, и публично он не документирован. Найти его можно только у себя: открыть настройки Under the Hood → DevTools → вкладка Network → фильтр graphql → искать запрос со словом UnderTheHood в имени операции. Дальше его можно повторить с вашими же куками. Никакого способа посмотреть метки чужого аккаунта в этом API нет — ключ запроса берётся из сессии, а не из параметра.

5Что внутри reportJson

Структура собирается функцией buildReportJson. Пример полного ответа (значения условные, поля и формат — реальные):

{
  "notes": "You can learn more about instances when a post's reach may be limited…",
  "period": { "startDate": "2026-07-01", "endDate": "2026-07-31", "timezone": "UTC" },
  "generatedAt": "2026-08-11T06:14:03Z",
  "postCount": 128,
  "postLabels": [
    {
      "label": "NSFW_HIGH_RECALL",
      "about": "Post detected by automated systems as one that may contain…",
      "effect": "Post hidden from recommendations to non-followers…",
      "posts": 3,
      "totalPostsInMonth": 128,
      "percentageOfPosts": "2.34%"
    }
  ],
  "accountLabels": [
    {
      "label": "SpamHighRecall",
      "about": "Account detected by automated systems as likely to post spam.",
      "effect": "The account's posts are hidden from recommendations to non-followers.",
      "days": 4,          // сколько дней месяца метка была активна
      "daysInPeriod": 31,
      "percentageOfDays": "12.90%"
    }
  ]
}

Чистый отчёт выглядит иначе: если меток нет, массивы пустые, а рядом добавляются поля "totalPostLabels": 0 и/или "totalAccountLabels": 0. Это и есть сигнал «ничего не навешано».

Разница в единицах измерения: посты считаются в штуках (posts — сколько постов месяца несут метку), аккаунт — в днях (days — сколько суток метка на вас висела).

8Чего отчёт не покажет

  • Предсказания на базе Grok. Системы, где Grok прогнозирует нарушение правил, в выгрузку не включены — вице-президент по продукту Кит Коулман объяснил это защитой от обхода правил спамерами.
  • Часть правил botmaker. В репозитории прямо написано, что некоторые правила не опубликованы «чтобы снизить риск обхода систем».
  • Разбивку по конкретным постам. Только агрегат: сколько постов за месяц несут метку и какой это процент.
  • Скоринг ранжирования. Насколько модель понизила ваш пост в ленте — не метка, и в отчёт не попадает.
  • Экспериментальный brand safety. Структуры UthBrandSafetyAggregate в схеме есть, но в коде помечены как «experimental / not used, всегда пустые, не отдаются в reportJson».

Итог по вашему вопросу. Отдельного «запроса к x.com» изобретать не нужно: единственная точка входа — страница Settings → Privacy and safety → Under the Hood у залогиненного аккаунта, и она же под капотом дёргает GraphQL-колонку, где идентификатор берётся из сессии. Если пункта нет — не хватает либо фиче-флага пилота, либо года возраста, либо десяти постов за отчётный месяц.
